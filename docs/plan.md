**Current scope - implemented first slice**

The current implementation follows the native Herdr crew flow in [README.md](../README.md), with local inspection available without Herdr.

- Run `captain` inside a Herdr workspace. Ask for Claude Code, Codex, or pi, rename its tab to **Captain Barbossa**, and replace the launcher with the selected native CLI.
- Recruit crew into deterministic declared tab shapes: `[placement] captain_tab` for the captain's tab and `crew_tab` for later tabs. Crew fill columns breadth first; explicit pane, tab, split, and direction flags override the grid for one recruit. See [placement.md](placement.md).
- Read optional project and global `.captain/settings.toml` files one key at a time, with project settings above global settings above shipped defaults, and CLI flags above all three. `captain init [--global]` writes the commented template. See [settings.md](settings.md).
- Use Herdr to create the selected topology and run a short session-local launcher there, then wait for the native agent to be ready before submitting its task.
- Focus existing crew by name with `captain focus Jack`, including natural-language navigation requests to the captain.
- Send an existing crew a follow-up prompt with `captain tell Jack 'message' --assignment ID`, which keeps its pane and conversation.
- Store graph memory in three scopes: session and project outside the repo, separated by canonical project path and Captain session, plus a curated `repo` scope committed as `.captain/graph.json` and shared by the team: an explicit `--scope repo` write only, with a closed relation vocabulary, a required `--because` rationale, deterministic sorted bytes that re-add as a no-op, and `--supersede` in place of newest-wins. `captain memory init [--from PATH] [--apply]` seeds it from the project rulebook (AGENTS.md, else CLAUDE.md) by a fixed markdown parse, previewing the facts until `--apply`. Query all three using the installed Graphify CLI.

There is no custom terminal UI, tmux layer, chat server, or background orchestration daemon.

**Done since**

- Crew signalling reads the native CLI's own hook events (Claude Code `--settings` hooks, Codex `notify`) from session-local event files, keyed by crew incarnation for new recruits and by crew name for legacy sessions, instead of scraping panes. Pane detection remains only as a fallback while no event has arrived; Codex's title-generation turn is filtered out.
- New crew have explicit incarnation and assignment IDs, declared owned paths and action grants, one pending question, and a required completion report. `tell --assignment` appends without replacing the original task; `ask`/`answer` carry question IDs, and `assign --handoff` requires acknowledged completion. Legacy crew retain their earlier follow-up behavior and are never silently adopted.
- `wait --json` exposes activity, questions, native approval prompts, explicit completion, uncertainty, timeout, and errors. Notifications remain pending until `--ack DELIVERY_ID`; native idle is not assignment completion. Uncertain terminal delivery requires inspection and `resolve`, never automatic resend. The pi captain bridge checks session-history ingestion before acknowledging and leaves uncertain events pending.
- `inspect files/read/search/state/git` provides bounded local JSON reads with literal project/scoped paths and fixed Git operations. Limits: 64 KiB output, 200 results, 10,000 entries, 8 MiB search content, five seconds. Git rejects unsupported config and repository layouts; filesystem deadlines are cooperative and native sandbox restrictions remain necessary. Crew state inspection is repo-only.
- Memory `show`/`path` are pure, scoped reads; legacy temp-root project graphs are read in place when durable state is absent. Full graph output retains its existing unbounded contract. Passive usage inspection reads cached prices only; `dashboard --refresh-prices` explicitly opts into refreshing a missing or stale cache.
- Publishing: the package is on PyPI as `captain-barbossa`. `release.yml` publishes `X.Y.Z.devN` from `uat` to TestPyPI and `vX.Y.Z` tags to PyPI, through trusted publishing with per-ref GitHub environments.
- Crew token-usage dashboard: `captain dashboard [--interval]` refreshes a plain-text table (`NAME AGENT STATUS CTX NOW CUM TOK CUM $ $/h`) for a session's crew. A `CAPTAIN` row leads it: the captain writes the same lifecycle events crew do, and its live status is matched by pane because it has no agent name. Every frame re-reads the roster, so crew recruited while it runs appear. Dismissed crew get no row; their cumulative tokens and cost stay in `TOTAL` and are disclosed by the annotation under it, so cumulative totals never shrink, while `TOTAL $/h` covers the current roster only and may fall. Unknowns stay unknown: `-` for unreadable usage, `$?` for unresolved pricing, `+?` on a partly unknown total, never a fabricated zero. The headers name the unit, because a cumulative count beside a percentage that resets reads as one number (Codex issue 3630): `CUM TOK`/`CUM $` are session-cumulative, `CTX NOW` is only the last API call. They do not compare - every call in a turn re-sends the whole context, so cumulative tokens run far ahead of the live context (a captain at 7% of a 1M window had billed 1.32M, 96% of it cache reads). `CUM TOK` is cumulative across the transcripts a crew has named, so `/clear` does not reset it; `CUM $` is a list-price estimate (counterfactual on a subscription) and `$/h` a trailing 10-minute rate. Prices come from LiteLLM's cache under the state root, with background refresh of missing or day-old data only on explicit `--refresh-prices`; `[dashboard] prices_file` overrides it. Context windows prefer the same LiteLLM data and fall back to a bundled table so `CTX NOW` works offline, with `[dashboard] context_limit` winning over both. Codex crew are read from their own rollout log (tokens, live model, context window); pi installs no hooks, so it renders "-". The frame fits the pane: short panes fold the overflow into one `MORE(N)` row, narrow panes shed the header line, then model names, then the bar (and the `NOW` qualifier with it), then `AGENT`, never the numbers. A captain launch opens it in a pane below itself only when `[dashboard] enabled = true`; `--no-dashboard` skips that enabled pane for one launch. It is re-nested under the captain when a crew splits into the captain tab (one deliberate tab flicker, since Herdr reparents only via another tab) and is never a split target itself.

The native agents use the small CLI commands through their existing tools. Follow-up scheduling, automatic integration of parallel edits, and provider transcript resume are outside this first implementation. See the README for exact behavior, setup, memory retention, and verification limits.
